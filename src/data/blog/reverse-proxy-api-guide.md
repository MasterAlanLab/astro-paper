## 中转

在介绍这些项目之前

我们需要先知道一个概念：API中转

现在全世界有很多个大语言模型厂商

国外的有 openai、anthropic、google

国内的有 minimax、阿里千问、智谱 等等

而我们作为消费者

一般来说有两种方式使用这些厂商的大语言模型

一是通过API直接调用，二是通过订阅套餐来使用对应的大语言模型

API就是按量付费，你说一句话就付一句话的钱

但是当你使用量比较大的时候，按量付费的费用会非常高，高到大多数人都用不起的地步

而订阅套餐里面则是包含了固定的额度，一般情况下比直接用API划算很多

以至于各个厂商的订阅套餐经常卖断货，供不应求

如果不太理解的话

你用手机号的话费套餐来类比，两种都是套餐，

电话号码是每个月有固定分钟数的免费通话时长

AI订阅套餐是每个月有固定的AI额度

有的平台是按token数计费，而有的平台是按请求次数计费

所以我看 token 翻译成词元还是不够人性化，应该叫词费才对

另外，现在的大语言模型厂商很多

不同厂商的大语言模型擅长的方向不一样

有的擅长任务规划，有的擅长设计UI，有的擅长编码

最终结果就是很多人同时买了多个厂商的API

最关键的是，这些AI套餐价格大多都挺贵的

一个人买了AI订阅以后

如果用不完就会很浪费

所以就有了统一管理多个厂商的API或者订阅套餐，以及多人拼车的需求

在这种情况下

各类API中转项目应运而生

## CPA

CPA 全称是 CLIProxyAPI

它还有个孪生兄弟 CLIProxyAPIPlus

一般情况下你就把 CLIProxyAPIPlus 当作 CPA 的超集

直接用 CPA plus 就好，毕竟CPA plus 支持的厂商更多

不过在视频中我还是用 CPA 来称呼

大家知道它还有个更强大的 plus 版本就好了

而 CPA 最核心的功能呢

就是把各个厂家的订阅套餐统一转换为 API

你可以在 CPA 上通过 oauth 的方式登录你的账号

比如我的账号订阅了 openai 的 plus 或者 team 套餐

而这些套餐中都是包含了 codex 的使用额度的

那么我就可以在 CPA 上通过 oauth 的方式登录我的 openai 账号

这样就可以把 codex 里面的额度通过 CPA 暴露为一个统一接口

让我本地的第三方的AI客户端

比如 cherry studio、alma 这些来使用 codex 里包含的 gpt 5.4 额度

这仅仅是一个 openai 账号，包含的AI额度很有限

很容易用到限额

于是我们就可以同时登录多个账号

把多个账号的额度汇总到一起

这样就能实现 token 自由

大家在网上看到的价格很低的 gpt 5.4 的套餐

99.9% 都是通过这种方式提供的

除了 openai 以外，CPA 也支持谷歌、anthropic、kiro等厂商的账号

不过要特别注意的是

这种共享订阅账号的方式一般情况下都是违反了厂商的使用协议的

容易被封号

大家使用的时候一定要注意

除了支持登录账号以外

CPA也支持添加自定义提供商

所以你可以把一些其它的中转站渠道都接入进来

在 CPA 中统一进行管理

前面这些说的都是 CPA 的功能、优点

那么CPA的问题是什么呢？

简陋！

CPA的整体实现实在是太简陋了

它后台就只有一个管理页

没有用户系统

也没有分组

它就是一个非常纯粹的聚合多个厂商的套餐为一个统一接口的项目

所以很多中转大佬在使用CPA的时候

都会再搭配其它的项目来实现分发

比如我们接下来要介绍的 newapi

## newapi

在中转站项目里

newapi 可以称得上是老资历了

newapi 起源于 one-api

但是 one-api 的作者进了大厂以后

截止目前已经有超过一年没有更新了

但是基于 one-api 二次开发的 newapi 还在一直保持更新

并且在 one-api 的基础上

增加了更多的功能，也修复了很多社区中提出来的问题

于是在社区中的热度也就越来越高

截止目前市面上绝大多数的中转站都是用 newapi 来部署的

像我们前面提到的 CPA 更多的适合个人使用，不适合用来分发给多个人使用

但是 newapi 则不一样

它属于是更专业的 API 中转平台

它能够更加方便的管理上游渠道

同步上游渠道的模型和价格

支持了更多的AI提供商

市面上主流的大语言模型基本上都可以通过 newapi 来中转

而且 newapi 内置了支付功能

包括易支付、stripe、creem

你只要按照官方指南填写上相关的支付配置

你的中转站就能轻松接入支付功能了

而不需要你做复杂的开发或者部署工作

当然 newapi 也不是没有缺点

当前这个环境下

主流厂商都在推AI订阅套餐

newapi 虽然说也支持了设置订阅套餐

但是目前功能还是比较鸡肋

不能够针对不同的分组设置不同的订阅套餐

它的套餐额度都是针对全中转站里的所有分组

对于同时有多个分组，而且不同分组的价格并不相同的中转站来说并不友好

所以 newapi 更加适合那种想要以按量付费的模式来分发大语言模型token的中转站站长。

那么有没有一个项目可以比较好的支持订阅套餐呢？

诶！还真有

那就是接下来要和大家分享的 sub2api

## sub2api

聊到 sub2api，

那就不得不提一下它的上一代--CRS

CRS 全称 claude relay service

在2025年五月，anthropic 在 Max 更新计划中把 claude code 纳入订阅以后

我们就可以通过购买 anthropic 的订阅套餐来使用最新的claude大语言模型

但是 anthropic 的套餐都很贵呀，而且官方限制了中国用户使用

有很多人想用最新的 claude 大语言模型，但是买一个套餐自己又用不完

还有些人手里有钱，但是苦于不懂网络，也没有办法使用上 claude 的大语言模型

于是就有人开发了 CRS

它的具体功能我就借用它自己的描述来介绍一下：

自建Claude Code镜像，一站式开源中转服务，让 Claude、OpenAI、Gemini、Droid 订阅统一接入，支持拼车共享，更高效分摊成本，原生工具无缝使用。

不过在更新了多个版本以后

作者发布了下 CRS 的下一代产品

也就是 sub2api

sub2api 的核心功能和 CPA 是相似的

都能够把多个厂商的AI订阅套餐转换为统一的API接口

不过 sub2api 从一开始走的就是多人共享的方向

它完善了用户管理、分组管理

也支持接入支付系统

无需任何开发就能轻松搭建起一套中转站

能够直接开始提供按量付费的服务

或者像厂商一样卖订阅套餐

支持每日限额、每周限额、每月限额

所以现在市面上有很多人都使用 sub2api 来卖token

但是和 newapi 相比

sub2api 支持的厂商太少了

默认只支持海外的AI大语言模型厂商

而且 sub2api 也不支持添加自定义提供商

看得出来 sub2api 更加偏向于做一个AI订阅合租平台

而不是一个大而全的大语言模型API中转站

因此 sub2api 更适合那些想要在小团队内共享海外的AI订阅套餐的小伙伴

可以很方便的针对每个人设置额度，限制并发

还能够清晰的通过监控看到每个人的使用量

但是目前有个最大的问题

这一类共享AI订阅的方式大概率是违反厂商的服务条款的

比如anthropic和谷歌就抓的很严格

如果你通过sub2api等项目共享订阅套餐

很大概率厂商会直接把你账号封了

当然，现在anthropic封号已经封魔症了

以至于网友们现在都把anthropic称为 A畜

相对来说，openai 反而成了大善人

gpt 5.4 量大管饱

所以不少人现在都转过头来使用 gpt 5.4

## 总结

视频的最后

我把这三个项目放到一起来做个对比

方便大家找到一个适合自己的中转项目

如果你是个人自用

希望将多个渠道的API汇总到一起进行统一管理

那么目前最佳选择应该是 CPA Plus

如果你主要使用国外的AI订阅套餐

同时你需要和其他人共享你的订阅套餐

那么目前的最佳选择是 sub2api

如果你的目标是想做一个大而全的 API 中转平台

希望能方便的接入多个上游渠道

支持接入更多的国产大语言模型

那么你就应该选择 newapi

当然也会有一些人会选择 newapi + CPA，或者 newapi + sub2api 这样的搭配

由 CPA/sub2api 将多个订阅套餐转换为API，再通过 newapi 来进行分发
