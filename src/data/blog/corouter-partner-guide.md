## 介绍

[ai.corouter.cc](https://ai.corouter.cc/) 是一个专注于 ChatGPT 等 AI 订阅代充值服务的网站。普通用户拿到卡密后，不需要注册平台账号，进入公开充值页面并填写必要信息，即可完成卡密校验和充值。

对于合伙人来说，平台提供了一套独立的业务后台。你可以在后台管理支付卡和账单信息、生成并分发卡密、查看充值记录与积分流水，也可以通过 API 把充值能力接入自己的销售网站。换句话说，合伙人主要负责支付资源、销售渠道和客户沟通，平台则负责卡密校验、充值工作流、订单状态及积分结算。

完整的业务流程可以概括为：

1. 使用邀请码注册合伙人账号；
2. 充值业务积分并准备支付卡；
3. 根据套餐和支付地区生成卡密；
4. 将卡密出售或分发给客户；
5. 客户在公开页面自助提交充值；
6. 在后台跟踪订单状态、积分流水和异常复核结果。

如果想先了解官方说明，也可以查看[合伙人机制与参与指南](https://ai.corouter.cc/partner-guide)。

## 开始前需要准备什么

正式生成卡密之前，需要先准备积分、支付地区和支付卡这三项内容。

### 1. 充值业务积分

积分是平台内部的业务结算单位，目前的充值比例为 **1 元人民币兑换 10 积分**。订单提交后，系统会先预扣积分，等支付结果明确后再完成结算，因此后台显示的账户余额和可用积分可能暂时不同：

> 可用积分 = 账户余额 - 预扣积分

建议在开始分发卡密前预留足够积分，并定期检查积分流水。如果可用积分不足，新订单可能无法继续处理。

### 2. 选择支付地区

不同套餐可能对应不同的支付地区、价格和税费。生成卡密前，应先确认自己支付卡支持的地区，再选择相应套餐和支付地区，避免因为卡片与地区不匹配导致付款失败。

### 3. 添加支付卡和账单信息

在合伙人后台添加用于代充的海外信用卡，并准确填写持卡人姓名、有效期以及账单地址等信息。如果暂时没有合适的卡片，可以通过[自助开卡渠道](https://cutt.ly/IyrMR4Mg)准备。

支付卡由合伙人自行维护。添加后建议先生成少量卡密，完整跑通一次“生成卡密—客户兑换—订单结算”的流程，确认卡片、地区和账单信息都能正常工作，再扩大分发规模。

## 生成和分发卡密

准备好积分与支付卡后，就可以在后台选择套餐和支付地区生成卡密。卡密可以直接发送给客户，也可以录入自己的订单系统，由自己的销售渠道完成展示和交付。

客户拿到卡密后的操作很简单：

1. 打开 [ai.corouter.cc](https://ai.corouter.cc/)；
2. 输入卡密并完成校验；
3. 按页面提示填写充值所需信息；
4. 提交后等待系统处理，并通过页面查看订单进度。

客户不需要注册合伙人后台账号。合伙人则可以在控制台查看自己名下的充值记录、处理状态和积分变化。为了方便售后，建议在发放卡密时同步记录自己的订单号、客户联系方式、卡密和发放时间，但不要在公开群聊中直接展示完整卡密。

## 通过 API 接入自己的站点

不开发网站也可以开展业务，直接在后台生成并分发卡密即可。如果已经有自己的商城或自动发货系统，则可以在控制台生成 API Token，通过合伙人 API 管理卡片、套餐、卡密及订单，让客户在自己的站点完成购买和后续流程。

接入时建议注意以下几点：

- API Token 仅保存在服务端，通过环境变量或密钥管理服务加载；
- 不要把完整卡号、CVV 或 API Token 返回给浏览器；
- 为创建卡密和提交订单的请求保存业务订单号，避免重复提交；
- 对接口超时设置合理的重试策略，超时不等于支付失败，应先查询原订单状态；
- 将平台订单状态同步到自己的订单系统，方便客户查询和售后；
- 正式上线前先用少量订单验证完整链路。

具体接口与字段以合伙人控制台里的 API 文档为准。

## 积分消耗和预扣规则

每次用户提交充值时，系统会先预扣 **10 积分**。预扣期间，这 10 积分仍显示在账户余额中，但不会计入可用积分。等订单结果确定后，再按照实际情况结算：

| 订单结果         | 最终消耗 | 积分处理方式                              |
| ---------------- | -------: | ----------------------------------------- |
| 充值成功         |  10 积分 | 将预扣的 10 积分正式结算                  |
| 平台原因导致失败 |   0 积分 | 完整释放预扣的 10 积分                    |
| 卡片原因导致失败 |   1 积分 | 释放 10 积分预扣，再扣除 1 积分失败服务费 |
| 等待人工复核     | 暂不结算 | 继续保留 10 积分预扣，确认结果后再处理    |

举个例子：账户余额为 50 积分，提交一笔订单后，后台会显示余额 50、预扣 10、可用 40。订单成功后余额变成 40；如果是平台原因导致失败，余额恢复为 50；如果是卡片原因导致失败，最终余额为 49。

这里所说的平台原因，通常包括平台配置、网络或内部基础设施异常；卡片原因则包括支付卡不可用、进入冷却期或付款被拒绝等。支付卡上的实际扣款和平台积分消耗是两套独立记录，积分的每一次变化都会出现在合伙人的积分流水中。

## 异常订单和人工复核

有时支付结果不能立即确认，订单会进入人工复核。此时系统会继续保留 10 积分预扣，并且不会重复发起支付。合伙人可以在后台的充值记录或人工复核页面查看进度。

复核完成后的处理方式如下：

- 确认充值成功：结算预扣的 10 积分；
- 确认未扣款：释放预扣的 10 积分；
- 确认已退款：释放预扣的 10 积分。

遇到待复核订单时，不要立即重新生成卡密或让客户重复提交，否则可能产生重复订单。应先保留订单号和相关状态，等待结果明确；如果长时间没有更新，再携带订单信息联系平台负责人。
